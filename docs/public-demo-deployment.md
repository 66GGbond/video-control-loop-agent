# 作品集公开体验版

## 已落实的体验规则

- 浏览网页、查看预置的控制计划与两轮质检案例免费，无需登录或体验码。案例标注为演示数据，不包含伪装成真实生成的视频。
- 第一次调用真实 AI（包括规划、质检、生成）时输入作者设置的四位数字体验码。没有预置、随机生成或写在前端的体验码。
- 同一个体验码在不同浏览器访客标识下各有 30 秒视频额度，不设体验码过期时间。额度、锁定和项目状态保存在服务端 SQLite 中。
- 用户界面只显示「体验码」「剩余视频额度」「已预留额度」，不显示设备归属和识别逻辑。
- 每次生成、修复生成都根据已确认的生成时长计额，提交前确认；当前适配器边界为每条 4–15 秒，可以生成两条 15 秒，不能生成单条 30 秒。
- 提交前原子预留，确认远端生成成功后扣除；明确失败或取消后释放。轮询超时不释放；远端已成功、本地下载失败仍计额。
- 提交请求超时等不明确结果会保留额度，防止重复生成。作者核对模型平台的任务记录后，通过后台命令处理，不自动退还可能已产生费用的任务。
- 刷新、重复输入同一码、重置项目和重启服务不重置额度。已有任务生成时不能重置项目。额度用完后仍可查看已有内容。
- 连续输入错误 5 次后永久锁定体验码输入（作者可解锁）；空输入、网络异常不计错，正确验证会清除此前连续错误。切换候选体验码不能绕过累计错误。
- 验证端点另有服务端 IP 限速（30 次/小时）和访客请求限速（10 次/分钟）。其他 AI 调用有独立的终身次数上限，默认 100 次/体验码/访客，防止规划或质检被无限调用；可设置 `TRIAL_AI_CALL_LIMIT`。

## 浏览器识别的边界

无需登录的普通网页无法可靠识别物理电脑。本实现以服务端签名、HttpOnly、SameSite 的持久 Cookie 为访客标识。同一浏览器正常关闭重开会保留额度；清除 Cookie、更换浏览器、无痕窗口会成为新访客。四位数字只有一万种组合，IP 限速可以降低猜码风险，但分布式攻击或不停更换访客身份仍可能绕过轻量限制。模型平台自身的消费上限可作为额外兜底。此边界不在产品提示中展示为设备身份信息。

体验码本身无过期时间，浏览器 Cookie 设置较长保留时间；浏览器仍可能按自己的隐私策略清除它。数据目录或数据库丢失会丢失额度和锁定记录，务必保留并备份。

## 本地配置与检查

```bash
cp .env.example .env
python3 scripts/configure_trial.py
# 编辑 .env，配置模型 API Key；不要提交 .env。
python3 -m unittest -q
python3 run_demo.py
```

打开 `http://127.0.0.1:8000`。没有配置体验码时网站仍能浏览、查看演示案例，付费功能保持关闭。`TRIAL_CODES` 支持逗号分隔多个作者设置的四位码；通常批量发送一个码即可。保留码值即可继续使用旧额度，删除码值即撤销该码的授权。

## 公网部署：完整后端服务

GitHub Pages 只能运行静态 HTML/CSS/JS，无法直接运行此项目的 Python 后端。需要一个支持常驻容器、持久磁盘和 HTTPS 的主机。以下配置不绑定具体云厂商，也不会自动购买服务器或创建付费资源。

当前交付包括 Dockerfile、Compose、Caddy 自动 HTTPS 入口。部署步骤：

1. 在你选择的主机上安装 Docker Engine 与 Compose，并拉取包含本改动的代码。
2. 将自有域名解析到主机，放行 80/443 端口。
3. 按上节设置 `.env` 中的四位体验码和模型 API Key，再设置 `SITE_DOMAIN=你的域名`。
4. 运行 `docker compose up -d --build`。Caddy 提供 HTTPS，应用和模型调用保留在后端，8000 端口不暴露到公网。
5. 通过域名分别测试无体验码案例、体验码锁定、真实生成与余额。需要进行真实生成时会产生模型费用。

Compose 将 Cookie Secure 和代理信任配置为开启。自建代理时，必须覆盖 `X-Trial-Client-IP` 为真实连接 IP 且禁止公网直连应用端口，才能设置 `TRUST_PROXY=1`；否则保持关闭以防伪造限速身份。平台前面还有 CDN 时，应在可信代理层明确处理实际来源 IP。

持久卷 `trial-data` 同时保存 SQLite、访客项目和生成文件。**不要执行会删除持久卷的 `docker compose down -v`。** 更新代码只需重新构建启动，保留原卷。当前使用单应用进程、单实例，SQLite 原子事务控制额度，进程内分组锁串行处理同一访客的请求；不适用于直接启动多个副本共享流量。

本地环境未安装 Docker，容器构建与公网 TLS 需要在实际主机上验证。Python HTTP 服务和自动化 API 测试已在本地验证；未调用付费模型。

## 普通网络与 VPN 的访问

前端不依赖第三方字体、脚本或图片 CDN；页面、脚本、样式和应用接口均为同一站点。访客不需要直连 DeepSeek、Ark 或 MiniMax；服务器负责连接模型服务，并将视频下载到站内提供预览。

这能减少跨域和第三方资源失败，但不保证任意运营商、VPN 节点或 DNS 都可访问。上线后应实测普通网络、手机流量和常用 VPN 出口，同时验证服务器至模型平台的连接。域名与主机的实际选址仍待作者确定。

## 后台维护（只在服务器终端执行）

```bash
# 使用 Compose 时，把下列 python3 命令前加上 docker compose exec app。
python3 -m backend.app.trial_admin locked
python3 -m backend.app.trial_admin unlock VISITOR_ID
python3 -m backend.app.trial_admin pending
# 先核对模型平台任务结果，再选择 used（已生成）或 released（明确未生成）。
python3 -m backend.app.trial_admin settle RESERVATION_ID --result released
```

这些命令不暴露为网页管理接口。记录中的访客标识和预留 ID 仅供作者后台维护，不出现在用户提示中。服务器重启后可以继续轮询已经保存任务 ID 的生成任务；极短的“远端已受理但本地尚未保存任务 ID”窗口需人工核对处理。
