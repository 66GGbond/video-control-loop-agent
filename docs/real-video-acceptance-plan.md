# 真实视频集中验收计划

## 目的与边界

本计划用于在更换或启用付费视频模型后，以尽可能少的生成次数验证 Video Control Loop Agent 的**端到端真实性**。它不是模型效果榜单，也不以“多生成几次直到好看”为目标。

每次付费运行都必须产出可复查的项目证据：控制计划、素材清单、生成合同、版本视频、抽帧证据、质量结论与下一步决策。

当前运行时可验证视觉质量和本地音轨存在性；除非 ASR、节拍或口型工具已接入，不应声称完成音频语义或音画同步验收。

## 集中运行前检查（不调用模型）

1. 确认 `.env` 中的 `VIDEO_PROVIDER`、模型 ID、API Key、分辨率与 API 基址匹配官方文档。
2. 重启本地服务，提交一个不含素材的短 Brief，确认 DeepSeek 返回 `planning_source = deepseek`，而非 `fallback`。
3. 为每个案例准备唯一命名的素材；只在要验收“参考一致性”时，使用 `@文件名` 显式关联。
4. 浏览控制计划，确认节拍数量、时长、比例、验收标准和素材清单均来自当前 Brief；不使用旧项目状态。
5. 每个案例只允许生成 V1；仅当 V1 出现有帧级证据支持的关键失败时，才批准 V2。

## 运行预算与停止规则

| 规则 | 执行方式 |
|---|---|
| 最小付费验证 | 先完成案例 A 的 V1；确认接口、下载、抽帧与视觉评估都正常后，才进入其他案例。 |
| 每案例默认预算 | `1` 次修复，即最多 V1 + V2。 |
| 不为“更好看”继续生成 | 已通过质量门的版本只记录结果；可选优化必须由用户明确授权。 |
| 视觉观察失败 | 保留 API/模型错误和运行日志，不把失败降级为示例评分。 |
| 证据不足 | 增加同一版本的采样或记录限制；不直接创建修复任务。 |
| 音频能力不足 | 仅记录音轨存在性；不让音频语义影响发布结论。 |

## 代表性案例

### 案例 A：产品结构与多参考素材

**目标**：验证有序 Asset Manifest、`@` 绑定、H3 多参考请求与产品完整性 Rubric。

- Brief：`为 @bottle-front.png 和 @bottle-side.png 制作 9:16 的 8–10 秒护肤精华广告。瓶身必须保持圆角方形、磨砂白色瓶盖和金色细字标签；展示拿起、旋转与正面定格。`
- 素材：两张产品参考图；可选一段氛围音频作为生成条件，但不作为音频语义通过条件。
- 控制计划应证明：产品结构、标签可读性和终态定格是原子验收项；两张图片按上传顺序进入 Asset Manifest；涉及产品一致性的标准含对应 `asset_bindings`。
- V1 验收：产品没有变形、重复瓶或不可读的必需标签；动作与定格均有对应帧证据。
- 若失败：V2 应为**整片重生成**，优先处理出现问题的语义节拍，同时保留通过的产品约束。

### 案例 B：角色连续性与动作完成

**目标**：验证参考角色、跨节拍状态记忆、风险感知抽帧和证据驱动修复。

- Brief：`@runner.png 在雨后的城市天桥上停下，取下耳机后看向远处驶来的列车。保持人物发型、外套颜色和耳机一致。`
- 素材：一张角色参考图。
- 控制计划应证明：规划的节拍数量来自动作状态变化，而不是固定三镜头；人物外观、耳机状态与关键动作被写为可见标准。
- V1 验收：抽帧覆盖动作前、动作中/后和最终反应；如果耳机消失、角色漂移或动作未完成，Bad Case 必须引用对应帧。
- 若失败：下一版任务需要明确说明“完整视频重生成，目标节拍为诊断优先级”，而非显示为局部镜头编辑。

### 案例 C：短广告的叙事与时长规划

**目标**：验证 DeepSeek 创意扩写、语义节拍数与时长规划是否随 Brief 改变。

- Brief：`制作一支 12 秒、9:16 的冰淇淋夏日广告：从闷热到入口后的清凉反转，最后产品特写。`
- 素材：无素材或一张产品参考图。
- 控制计划应证明：模型补全可执行的画面、镜头和感官细节，但不捏造品牌、口号或用户未提供的事实；节拍与时长总和符合 4–15 秒单片边界。
- V1 验收：每个计划节拍都有对应证据；不能因为画面好看而忽略“情绪反转”“产品特写”等关键标准。
- 若失败：根据证据判断是提示冲突、镜头复杂度过高还是取证不足；不以固定模板生成 V2。

## 每次运行的记录模板

将以下内容保存到 `docs/evidence/`（不提交 API Key、原始私密素材或包含个人信息的文件）：

```text
case: A_product_manifest
date:
provider/model:
generation contract id:
evaluation contract id:
assets: [R1 ..., R2 ...]
planned duration / ratio:
V1 release decision:
V1 failed critical criteria and cited frames:
V2 authorised? why:
V2 release decision (if any):
observed product / agent limitation:
```

每个成功案例至少保留四张截图：控制计划、素材清单/执行轨迹、Version Review + Quality Rubric、Bad Case 或 Release Gate。视频本体是否公开由素材版权和平台条款决定。

## 通过标准

一次集中验收可视为完成，当且仅当：

1. 至少一个真实案例完成“规划 → H3 提交 → 视频下载 → 风险感知抽帧 → 视觉评估”的全链路；
2. 至少一个案例证明多参考素材在生成合同中按顺序保留，且 `@` 绑定影响参考专项验收；
3. 至少一个失败或刻意设置的高风险要求产生可引用的 Bad Case，并导致合乎预算的下一版决策；
4. 任一版本分数在后续版本生成后保持不可变；
5. README 只展示实际观测到的能力与限制。
